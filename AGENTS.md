# AGENTS.md

## Project Layout

- This repo is a multi-package app with separate `package.json`, lockfile, and `node_modules` per package: backend at repo root, frontend in `web/`, docs in `docs/`, and OpenCode helpers in `.opencode/`.
- Backend entrypoints are `src/main.ts` and `src/app.module.ts`; Nest modules live one-per-domain under `src/`.
- Frontend entrypoints are `web/src/main.tsx` and `web/src/App.tsx`; API calls use `web/src/common/constants.ts` with `API_BASE_URL = '/api'`.
- `docs/` is a Docusaurus 3 site, not part of the backend/frontend builds.

## Commands

### Backend, From Repo Root

```bash
npm run start:dev          # Nest dev server; .env PORT=8000 in local dev
npm run build              # nest build; excludes web/ and docs/
npm run lint               # eslint with --fix and type-aware rules
npm test                   # Jest unit specs under src/**/*.spec.ts
npm test -- stats.service  # focused Jest run by name/path pattern
```

### Frontend, From `web/`

```bash
npm run dev                # Vite dev server, host enabled
npm run build              # tsc -b then vite build
npm run lint               # eslint .
```

### Docs, From `docs/`

```bash
npm run start              # Docusaurus dev server
npm run build              # Docusaurus production build
npm run typecheck          # tsc
```

### Prisma, From Repo Root

```bash
npx prisma generate --config prisma.config.ts
npx prisma migrate dev --config prisma.config.ts --name <name>
npx prisma migrate deploy --config prisma.config.ts
```

### Docker

```bash
docker compose up -d                         # db only; app services are behind prod profile
docker compose --profile prod up -d --build  # backend + frontend + db
```

## Prisma And Database

- Always pass `--config prisma.config.ts`; `prisma.config.ts` points at the schema directory and loads `.env` via `dotenv/config`.
- Prisma schema is split across `prisma/schema/*.prisma`, not a single root `schema.prisma`.
- The generated Prisma client is committed/generated at `src/generated/prisma`; import from `../generated/prisma/client`, not from `@prisma/client`.
- `PrismaService` uses `@prisma/adapter-pg` (`PrismaPg`) and `DATABASE_URL`; inject `src/prisma/prisma.service.ts` instead of constructing clients directly.
- `Parcela.geom` is `Unsupported("geometry(Polygon, 4326)")`; geometry reads/writes need raw SQL or existing service patterns.
- Local DB expects PostgreSQL with PostGIS. `init/dbinit.sql` seeds `Pais`, `Provincia`, and `Poblacion` reference data.

## Backend Notes

- `tsconfig.json` uses `module: "nodenext"` and `moduleResolution: "nodenext"`.
- `nest-cli.json` copies `src/templates/*.hbs` and `src/ai/prompts/*.hbs` into `dist/src` and enables the `@nestjs/swagger` plugin.
- Swagger is served at `/docs` by `src/main.ts`; DTO metadata is generated by the Nest Swagger plugin.
- `ConfigModule.forRoot()` loads `.env`; required variables are listed in `.env.example`.
- Local backend defaults to port `3000`, but `.env.example` sets `PORT=8000`; Vite proxy targets `localhost:8000`.
- The `test:e2e` script references `test/jest-e2e.json`, which is not present in the repo.

## Frontend Notes

- TailwindCSS 4 is wired through `@tailwindcss/vite`; there is no `tailwind.config.js`.
- DaisyUI 5 classes are used, but DaisyUI is a dev dependency/plugin dependency rather than a visible config file.
- Vite proxies `/api/*` to `http://localhost:8000` and strips the `/api` prefix.
- `web/tsconfig.app.json` is strict and enables `noUnusedLocals`, `noUnusedParameters`, `verbatimModuleSyntax`, `erasableSyntaxOnly`, and `noUncheckedSideEffectImports`.
- React Router routes are defined in `web/src/App.tsx`; providers are composed in `web/src/main.tsx`.

## Deploy And Infra

- Pushes to `main` or `develop`, plus manual dispatch, trigger `.github/workflows/deploy.yml`.
- Deploy SSH script force-resets the remote checkout, runs `docker compose --profile prod up -d --build`, then `docker compose exec acv-compare-backend npx prisma migrate deploy`.
- Docker maps backend `8080:3000` and frontend `80:80`; `olca` is an external Docker network required by the prod profile.
- Backend Docker image runs `npx playwright install chromium --with-deps` for report generation.

## OpenCode Files

- `opencode.json` and `.opencode/` configure repo-local OpenCode providers, commands, and skills; use the `customize-opencode` skill before editing them.
