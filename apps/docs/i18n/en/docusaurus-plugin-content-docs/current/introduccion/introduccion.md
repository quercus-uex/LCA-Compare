# Introduction

The system is made up of two independent services that work together to provide a complete solution for calculating, visualizing, and comparing the **Life Cycle Assessment (LCA)** of agricultural crops.

## Services

### LCA Bridge

**LCA Bridge** is a **Python** microservice built with **FastAPI** that acts as a bridge between the **LCA Capture** platform and the **openLCA** LCA calculation engine, using a database in **.zolca** format. It receives agronomic crop data (plot, crop type, inputs, irrigation, machinery, and so on), runs the environmental impact calculation by delegating to the openLCA IPC server, and sends the structured result to LCA Compare.

The service exposes a single endpoint, `POST /capture-acv`, and automatically selects the appropriate calculation process according to the crop type (`TomateProcess`, `OlivoProcess`, or `VinedoProcess`).

### LCA Compare

**LCA Compare** is a web application composed of a **NestJS backend** and a **React frontend**. It handles persistence, visualization, and comparison of LCA results generated by LCA Bridge. Its main features include:

- Plot management with **SIGPAC**, **Catastro**, and Portuguese property identifier integration for geospatial representation.
- LCA result visualization broken down by impact category (fertilizers, crop management, pesticides, irrigation system, and total impact).
- Comparison between two crop sets with filters by location, crop type, campaign, and more.
- Global statistics dashboard with KPIs, time evolution, territorial rankings, and crop distribution.
- PDF report generation with summaries and recommendations assisted by **AI** (OpenRouter).
- Administration panel for users, plots, crops, impact methods, and territorial data, with JWT authentication.

## How They Interact

Both services communicate through a **shared Docker network** (`olca`), enabling a decoupled data flow:

1. **LCA Capture** sends crop data to the **LCA Bridge** `POST /capture-acv` endpoint.
2. **LCA Bridge** calculates the environmental impact in **openLCA** and builds the structured result.
3. The result is sent through a `POST /capture` request to the **LCA Compare** backend, which persists it in PostgreSQL and links it to the corresponding user, plot, and crop.
4. The user can view the results, compare them with other crops, and generate reports from the **LCA Compare** web interface.

Result delivery from LCA Bridge to LCA Compare is performed in *best-effort* mode: if LCA Compare is not available, the error is logged without interrupting the client response.
