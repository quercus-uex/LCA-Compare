# Introduction

The system is made up of two independent services that work together to provide a complete solution for calculating, visualizing, and comparing the **Life Cycle Assessment (LCA)** of agricultural crops.

## Services

### Capture ACV

**Capture ACV** is a **Python** microservice built with **FastAPI** that acts as a bridge between the **DTAgro** platform and the **openLCA** LCA calculation engine, using a database in **.zolca** format. It receives agronomic crop data (plot, crop type, inputs, irrigation, machinery, and so on), runs the environmental impact calculation by delegating to the openLCA IPC server, and sends the structured result to ACV Compare.

The service exposes a single endpoint, `POST /capture-acv`, and automatically selects the appropriate calculation process according to the crop type (`TomateProcess`, `OlivoProcess`, or `VinedoProcess`).

### ACV Compare

**ACV Compare** is a web application composed of a **NestJS backend** and a **React frontend**. It handles persistence, visualization, and comparison of LCA results generated by Capture ACV. Its main features include:

- Plot management with **SIGPAC**, **Catastro**, and Portuguese property identifier integration for geospatial representation.
- LCA result visualization broken down by impact category (fertilizers, crop management, pesticides, irrigation system, and total impact).
- Comparison between two crop sets with filters by location, crop type, campaign, and more.
- Global statistics dashboard with KPIs, time evolution, territorial rankings, and crop distribution.
- PDF report generation with summaries and recommendations assisted by **AI** (OpenRouter).
- Administration panel for users, plots, crops, impact methods, and territorial data, with JWT authentication.

## How They Interact

Both services communicate through a **shared Docker network** (`olca`), enabling a decoupled data flow:

1. **DTAgro** sends crop data to the **Capture ACV** `POST /capture-acv` endpoint.
2. **Capture ACV** calculates the environmental impact in **openLCA** and builds the structured result.
3. The result is sent through a `POST /capture` request to the **ACV Compare** backend, which persists it in PostgreSQL and links it to the corresponding user, plot, and crop.
4. The user can view the results, compare them with other crops, and generate reports from the **ACV Compare** web interface.

Result delivery from Capture ACV to ACV Compare is performed in *best-effort* mode: if ACV Compare is not available, the error is logged without interrupting the client response.
