# Development Environment

## DevContainer

For service development, [DevContainers](https://containers.dev) were used. They are a Docker-based solution that provides isolated environments for each development setup. To use it, open the service repository in an IDE with DevContainer support enabled (Visual Studio Code, PyCharm, and so on).

## Dependency Installation

Once inside the DevContainer, create a Python 3.12+ virtual environment and install dependencies:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

## [OpenLCA IPC Server](https://github.com/GreenDelta/olca-ipc-container)

The service requires a running OpenLCA IPC server. The OpenLCA database must be available at `openlca-docker/data/databases/bafu`. To start the IPC server, deploy that Docker Compose service:

```bash
docker compose up openlca-ipc
```

## Start the Development Server

To start the server in development mode with hot reload, run the following command inside the `src/` folder:

```bash
fastapi dev
```

Swagger documentation is available at `http://localhost:3000/docs`.

## Testing

Tests use **pytest** with the **Starlette** test client. Fixtures are located in the `test/` directory:

```bash
# Run all tests with coverage (recommended — equivalent to CI)
tox -e py

# Run a specific test file
pytest test_main.py

# Run an individual test
pytest test_main.py::test_dtagro_acv_valid
```

:::note
The valid input test (`test_dtagro_acv_valid`) expects an **HTTP 500** status code instead of 200 because the OpenLCA server is not available in the CI environment.
:::

There is no configured linter, formatter, or typechecker.

## Model Generation

The `src/models/dtagro_acv_output.py` file is automatically generated from the `schema/dtagro_schema_v1.json` JSON schema. It must not be edited manually. To regenerate it after modifying the schema:

```bash
bash utils/generate_output_model.sh
```

## Project Structure

```
.
├── src/                              # Service source code (Python)
│   ├── main.py                       # FastAPI application entry point
│   ├── acv_service.py                # ACVService: main calculation logic
│   ├── routers/                      # Endpoint definitions
│   ├── services/                     # OLCAClient and process management
│   ├── models/                       # Pydantic models
│   │   └── dtagro_acv_output.py      # Autogenerated from schema/
│   ├── processes/                    # Crop-type-specific processes
│   │   ├── tomate_process.py         # TomateProcess
│   │   ├── olivo_process.py          # OlivoProcess
│   │   └── vinedo_process.py         # VinedoProcess
│   └── templates/                    # Templates for LCA calculations
├── schema/
│   └── dtagro_schema_v1.json         # JSON schema for model generation
├── utils/
│   └── generate_output_model.sh      # Model regeneration script
├── test/                             # Tests and fixtures
├── openlca-docker/                   # Maven/Java IPC server project (independent)
│   └── data/databases/bafu/          # .zolca database path
├── requirements.txt                  # Python dependencies
├── Dockerfile                        # Service image
├── docker-compose.yml                # Orchestration (openlca-ipc + bridge)
├── tox.ini                           # tox configuration for testing
└── .devcontainer/                    # DevContainer configuration
```
